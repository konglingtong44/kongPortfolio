# 03 故障恢复图

本次 Story：复用 01 架构图、02 CI/CD 的节点、连线动画、悬停／聚焦说明和下方详情；删除模拟说明条和独立播放器。

按恢复机制整理为 5 类，不把原来的 01–08 当作故障的完整清单：

| 类别 | 内部情况 |
|---|---|
| 验证失败 | 构建／STG、Green 直接验证 |
| 审批拒绝 | 审批①、审批② |
| 后端发布中恢复 | 人工发现业务异常、部署脚本检查失败、CodeDeploy 部署失败、CloudWatch 告警 |
| 前端恢复 | 发布脚本仍运行、发布完成后人工恢复 |
| 后端发布后重新发布 | 部署及观察脚本均结束后的 API 故障 |

判断依据：`scripts/deployment-contract.mjs`、`scripts/frontend-release.mjs`、`scripts/green-contract.mjs`、`infra/terraform/cicd/deployment.tf` 和候选流水线定义。

关键边界：部署成功但观察脚本未退出时，脚本仍可能通过另一个 CodeDeploy 部署恢复 Blue；脚本退出后的重新发布需要新的两道审批。前端 LIVE 前失败不改变生产路由，LIVE 后的自动恢复可能失败。恢复候选发布失败时，其回滚基准也可能仍是故障版。

验收：三页节点均为 180×90，弹出说明样式与 `route-travel` 动画一致；零流量线路不播放请求动画；切流前保持 Blue 100%；五类所有内部情况支持三语。使用本地测试与浏览器检查，不将其记为 AWS 故障演练。
