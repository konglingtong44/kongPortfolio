后续源码978a636已通过AWS前端73项及生产构建，和STG24后端组成同次候选；第一审批后Green20真实角色问答／冷启动通过，执行61bcc02c…等待第二审批。第二审批会授权生产切流及新网页发布；目前网页尚未发布，没有公网STG页面。以下15组浏览器证据使用本地模拟接口，不等于真实浏览器到STG问答E2E。见[本次候选](bedrock-candidate-approval.md)。

验收：沿用现有入口及像素弹窗；日／中／英可选问题、回答、范围提示和等待／错误状态可用；兼容生产准备状态，不在打开时调用模型；保持手机滚动与嵌套弹窗操作。

- 打开只GET `/api/bedrock/questions?language=ja|zh|en`，从后端读取17个审核问题，不把简历或问句表复制进前端。选择问题后点击提问，才POST `{message, language}`；不传history、system、模型ID或凭证。
- 仅提供问题选择入口。确定性的白名单及费用限制仍由Java执行；前端禁用按钮不能防止其他客户端绕过。
- 展示ANSWER、REFUSED及截断提醒；回答以React文本节点呈现，保留换行，不解析HTML。切换问题清除旧回答，窗口关闭／语言变化取消等待，后续响应不再写入旧窗口。
- 目录等待8秒、问答等待32秒；504显示超时，429按Retry-After等待（当前后端60秒），503显示暂不可用。不自动重试模型请求；浏览器取消等待不保证云端已经停止或免除调用费。
- 新目录enabled=false显示准备中；旧生产目录404时仅补一次空POST准备状态探测，没有问题正文，不触发模型。网络或畸形响应显示错误，不伪装成成功。
- 沿用日语优先、浏览器语言识别及手动选择持久化；不保存访客问答到localStorage。

本地验证：前端73项／生产构建通过；Chrome桌面1366×900、手机390×844／320×568，WebKit390×844／844×390，三语共15组检查通过。验证17选项、点击前0推理请求、提交字段、长回答滚动、无横向溢出、关闭后父弹窗保留、焦点恢复和页面滚动恢复。回答来自明确标注的本地模拟接口，没有AWS／模型调用，不等于真实浏览器到STG的端到端验收，也不等于iPhone真机验证。修正了浏览器原生dialog关闭前恢复焦点失败，以及WebKit鼠标点击入口不自动聚焦的问题。
