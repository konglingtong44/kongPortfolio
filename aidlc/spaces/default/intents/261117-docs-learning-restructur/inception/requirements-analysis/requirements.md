# 文档与目录重构需求

## 依据与意图分析

本次需求来自[目标说明](../../ideation/intent-capture/intent-statement.md)、[范围说明](../../ideation/scope-definition/scope-document.md)和[已确认答案](requirements-analysis-questions.md)。现状依据是代码知识库的[项目概览](../../../../codekb/kongPortfolio/business-overview.md)、[架构](../../../../codekb/kongPortfolio/architecture.md)与[代码结构](../../../../codekb/kongPortfolio/code-structure.md)。知识库的深读范围为部分仓库；清理具体文件前仍须核实其引用与用途。

目标是让完全不懂 AI、软件技术和 AWS 的读者沿一条中文路线理解项目，并让维护者找到每个项目手写文件的作用、以后修改规则或增加流程的入口。文档清理须建立在可核对证据上；“引入 AI-DLC”本身不证明其他文件无用。

## 功能需求

| ID | 优先级 | 要求与可核对的验收条件 |
|---|---|---|
| FR1 | 必须 | 建立零基础中文阅读入口。给定首次打开 `docs/learning/` 的读者，当按入口顺序阅读时，应能依次找到项目用途、网站与 API、技术框架、AI、AWS、文件地图、规则与流程入口；首次出现的术语须用日常语言解释。入口失效时文档检查应报出具体路径。 |
| FR2 | 必须 | 建立项目文件地图。逐一列出版本管理中由项目维护的手写文件，写明路径、所属功能、用途和需要修改的时机；每个有效项目目录说明目的。AI-DLC 安装件、自动下载或构建产物按目录与类别说明来源与管理者。找不到或无法核实的路径应明确标为待核实，不得写成已覆盖。 |
| FR3 | 必须 | 整理现有 `docs/learning/`。新增入门路线，保留有用文章供深入阅读；逐篇核对重复和过时内容后合并或修正。原有有效链接、历史事实与日期语境必须可从新入口找到；不能把过去的发布记录写成当前线上状态。 |
| FR4 | 必须 | 解释项目实际技术。按前端、后端、本地运行、基础设施、交付和 AI 分别说明技术或框架的用途、选择带来的好处及常见替代方案。每项比较须标明“项目已有决策”或“教学比较”；源码仅声明但未经线上核实的能力须标为配置或实现，不声称已部署。 |
| FR5 | 必须 | 写清维护入口。读者应能找到手动修改项目约定、AI-DLC 方法规则、项目自定义技能、学习资料和增加项目流程的位置，并理解框架生成文件与项目自写文件的区别。说明改动后需运行的现有检查及哪些变更不该直接改生成文件。 |
| FR6 | 必须 | 在任何实际移动、合并或删除前提交文件级清理方案。每个候选列出路径、现有用途、引用或无引用证据、历史保存价值、影响、验证方式和回退方式；经项目负责人审核后才执行。不能仅凭文件名、日期或 AI-DLC 已安装判定无用。 |
| FR7 | 必须 | 分小步实施已审核的整理。第一步交付学习入口与阅读顺序，后续逐步补齐文件地图、技术说明和清理；每一步列明验收条件、改动、检查结果与未验证项并暂停审核。文件移动时更新仓库内引用及相对链接。 |
| FR8 | 必须 | 保持项目现有网站和 API 行为及 AWS 资源边界。若整理依赖、脚本或配置，先核对调用方和验证路径；改变访客行为、Terraform 状态或线上资源的方案不得混入本次工作。 |

## 非功能需求

| ID | 优先级 | 可验证要求 |
|---|---|---|
| NFR1 | 必须 | 文档可导航：任何已纳入入口的本地 Markdown 链接均应通过 `node scripts/check-docs.mjs`，报告范围、退出结果和未覆盖的远程链接或锚点。 |
| NFR2 | 必须 | 事实可追溯：技术、AI、AWS 和文件用途的当前事实需指向代码、配置或现行文档；未深读、未运行、未查询 AWS 的部分明确标出，不用推测填空。 |
| NFR3 | 必须 | 安全：不把密钥、密码、`.env`、证书、Terraform state 或私有资料纳入学习文档与 AI-DLC 知识库；不触发付费 AWS 资源或真实付费模型采样。发布前遵守项目的秘密扫描约定。 |
| NFR4 | 必须 | 兼容与回退：每个已批准的移动或删除保持有用入口可达，并能按文件级方案恢复；配置或脚本改动须运行相应的前后端及本地检查，未运行的检查明确记为未验证。 |
| NFR5 | 必须 | 可维护：文件地图以稳定目录和文件路径为索引，标明资料核对日期及更新入口；新增、移动或移除项目手写文件后可以据此更新地图，不要求靠读者猜测生成目录内部结构。 |

## 约束

- 项目维持 React/TypeScript/Vite、Java 21/Spring Boot、Docker/Compose 和现有 Terraform AWS 目标；没有项目数据库，ECS/ALB 只是延期练习。不得因为教学比较而引入替代框架。
- 网站与 API 对访客的现有行为、日语优先及中英文支持、已接受的移动端布局保持不变。AWS 实际资源和生产审批门不在本轮修改范围。
- 项目负责人是唯一范围决定人；历史记录和具体删改逐项审核。无需额外汇报或固定截止日期。
- 使用现有 `docs/README.md`、`docs/architecture/overview.md`、`docs/deployment/README.md` 与 `docs/stories/` 的导航约定；文档搬移后运行项目链接检查。

## 假设与边界处理

- 学习资料以中文为讲解语言；网站已有日中英界面不因文档语言改变。依据是本次中文请求和已确认的中文阅读入口。
- “逐一说明文件”指项目手写且纳入版本管理的文件；自动下载、构建产物和 AI-DLC 生成文件按类别解释，依据[目标阶段答案](../../ideation/intent-capture/intent-capture-questions.md)。
- 遇到路径不存在、引用失效、同一文件多处提及、名称带空格或非 ASCII 字符时，文件地图保持真实路径且不重复计数；无法核实则列为待核实，不静默删除。仓库外或被忽略的私有文件不纳入盘点。
- 仓库中的 AWS 和 Bedrock 配置、历史发布记录只能证明相应时点的代码或记录；没有本轮线上查询就不能证明当前部署状态。

## 本轮不包括

- 新增网站、API 或 AI 功能；改变访客可见行为。
- 创建、修改、部署 AWS 资源，或取消已有两个生产审批门。
- 要求零基础读者独立完成本地运行；材料可说明入口，但不扩展成完整操作课程。
- 未经证据和文件级审核直接清空旧文档、历史记录、脚本、依赖或环境配置。

## 待后续核实

具体清理路径、引用和历史价值由后续文件级方案核实；当前代码知识库只对部分仓库做了深读。审阅这些路径前不作删除判断。
