# 文档与目录整理工作清单

这是一份初步工作清单，承接[目标说明](../intent-capture/intent-statement.md)和[范围说明](scope-document.md)。具体文件路径与独立实施单元要在仓库盘点后确定。优先级采用“必须完成／本轮不做”，不把尚未核实的文件预先标为删除。

| 编号 | 能交付的结果 | 优先级 | 前提与先后 | 验收要点 |
|---|---|---|---|---|
| I1 | 零基础学习入口与阅读顺序 | 必须；第一份可审核成果 | 先核对现有入口与主要目录 | 读者能从一个入口依次找到项目用途、技术、目录与后续主题 |
| I2 | 按功能组织的文件地图 | 必须 | 盘点现有目录、手写文件与生成内容 | 各有效目录和手写文件有用途说明；工具自带或生成内容有类别说明 |
| I3 | 技术、AI 与 AWS 的学习说明及替代方案比较 | 必须 | 依据实际项目技术与部署资料 | 对每项实际使用的主要技术说明作用、好处、区别；教学比较与真实决策分开标注 |
| I4 | 手动修改规则与增加流程的入口 | 必须 | 确认 AI-DLC、项目约定和自定义文件的职责 | 读者能找到该改哪里、为什么改那里 |
| I5 | 重复或过时资料与配置的候选清单及整理 | 必须 | I2 的用途和引用核对；历史资料另核保存价值 | 每项删改先有路径、证据、影响、验证和回退说明并经你审核 |
| I6 | 链接、资料准确性与行为保持检查 | 必须 | 每个实际改动之后 | 文档链接和相关本地检查结果可复核；明确写出未运行的检查 |
| I7 | 面向零基础读者的完整本地运行教程 | 本轮不做 | 若以后需要，可另立小改动 | 不作为本次验收条件 |

## 价值顺序

先交付可读的学习入口，再补齐文件地图、技术说明和维护入口；有了可核对的现状，才逐项处理清理候选。实际执行时允许把必要的现状核对放在第一份入口之前，以免把旧配置写成当前事实。参见[范围问题与答案](scope-definition-questions.md)中的 Q1–Q4。

## 审核边界

历史记录可进入候选，但不能因“旧”而直接删除。涉及依赖或配置的删改须先提交文件级方案，说明网站与接口现有行为如何验证；AWS 资源不在本次修改范围。参见[范围说明](scope-document.md)。
