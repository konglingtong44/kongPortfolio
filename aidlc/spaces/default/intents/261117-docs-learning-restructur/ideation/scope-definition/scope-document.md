# 文档与目录整理范围

## 目的与依据

本次工作按[已批准的目标说明](../intent-capture/intent-statement.md)开展：让零基础读者按顺序理解项目，并让维护者安全识别过时、重复的资料与配置。问题文件记录了首个成果、历史记录、技术比较和时间边界的选择。参见[范围问题与答案](scope-definition-questions.md)。

## 本轮包括

| 成果 | 边界 | 完成时可检查的证据 |
|---|---|---|
| 零基础学习入口 | 按阅读顺序解释项目用途、技术、AI、AWS、文件夹与文件类别 | 有一条连续阅读路径；每个主题能从入口找到 |
| 项目文件地图 | 按功能说明目录；说明项目手写文件的作用，以及 AI-DLC 自带、下载或生成内容的类别 | 已盘点的有效项目目录和手写文件有用途说明；生成内容标明来源 |
| 技术比较 | 对项目使用的技术说明好处、差异和常见替代方案 | 每项比较标明“项目实际决策”或“教学比较”；不捏造曾做过的评估 |
| 规则和流程入口 | 说明以后手动修改项目规则、增加流程应去哪里 | 学习资料中有可查找的维护入口及用途说明 |
| 安全整理 | 评估重复、过时的文档、依赖、环境配置、项目自定义规则、技能和辅助脚本 | 每个拟移动、合并或删除的目标先列明路径、在用证据、影响、验证和回退方式，再交你审核 |
| 历史记录评估 | 历史资料也可列为候选，但不能仅凭日期判断无用 | 逐项说明保存价值和删除影响；未获你对具体清单的审核时不删除 |
| 行为保持与检查 | 修改后网站和接口的现有行为不变，AWS 资源不变 | 记录与改动相关的本地检查结果和未验证项；不把本地检查写成线上验证 |

## 本轮不包括

- 新的网站或接口功能，以及访客可见行为的删改。
- 创建、修改或部署 AWS 资源。
- 把“零基础读者独立照文档运行项目”作为本轮完成条件；必要的现有运行入口可以解释，但不扩成新的完整教程。
- 尚未盘点便宣布某文件无用，或把教学用替代方案写成项目实际做过的决策。

## 最小可审核成果与顺序

第一份可交给你看的成果是零基础学习入口和阅读顺序。为保证内容准确，先核对当前项目的目录与技术，再写这一小份入口；后续再扩展文件地图、技术比较和清理清单。每个小改动分别写出验收条件、执行、验证和未验证项，交你审核。没有固定截止日期。参见[已批准的目标说明](../intent-capture/intent-statement.md)及[范围问题与答案](scope-definition-questions.md)。

| 读者／维护者要完成的事 | 接触的成果 | 得到的价值 |
|---|---|---|
| 零基础读者从入口开始 | 阅读顺序 → 项目概览 → 文件地图 → 技术与替代方案 | 逐步理解项目，知道到哪里继续看 |
| 项目维护者判断资料能否清理 | 现状清单 → 文件级候选与影响 → 审核 → 修改与验证 | 看清删改依据，保留可回退和可核对的记录 |
| 项目维护者以后调整做法 | 规则与流程入口 → 对应文件或命令 | 找到手动维护位置，不把框架文件与项目自定义内容混淆 |

## 依赖与决定权

- 文件地图和技术比较以实际仓库盘点为前提；清理清单以用途、引用和历史价值的核对为前提。
- 你是范围和优先级的唯一决定人。历史记录或配置的具体删除，以及其他文件级改动，先给你审核，再实施。
- 本阶段只确定内容边界和优先顺序；具体路径和删改项在盘点、设计之后列出。
