# 项目文档与目录整理意图

## 问题

项目经历了学习和多轮迭代，仓库里可能留下重复、过时的说明文档与环境配置。项目维护者希望查明哪些仍在使用、哪些可合并或删除，并让零基础读者看懂整个项目；现有资料是否重复、哪些文件确实无用，仍须盘点验证。 [desc][Q7]

## 目标读者

- 完全不懂 AI、软件技术和 AWS 的读者：需要按顺序认识项目的用途、所用技术及目录中的内容。 [desc][Q1][Q2]
- 项目维护者：需要知道文件用途，以及以后到哪里修改项目规则或增加流程。 [desc][Q2]

## 成功指标

- 学习资料按功能列出各文件夹的目的，逐一说明项目手写文件的用途，并按目录和类别说明 AI-DLC 自带、下载或自动生成的内容。 [Q1]
- 阅读路径涵盖项目用途、实际采用的技术、AI、框架和 AWS 组件；对项目确实涉及的选型，说明采用方案的好处、与相关替代方案的区别及选择理由。 [desc][Q2][Q6]
- 读者能沿资料找到文件用途，以及以后手动修改规则和增加流程的入口。本轮不以读者独立运行项目作为完成条件。 [desc][Q2]
- 每项拟删除或合并的旧资料、依赖与配置，都有可核对的用途和影响说明；网站与接口的现有行为保持不变，AWS 资源不变。 [Q5][Q6][Q7]

## 启动原因

项目已经引入 AI-DLC，而此前为学习创建的文档和环境配置经过迭代，可能仍有过时或重复项；因此现在需要核对现状并建立清楚的学习入口。 [desc][Q7]

## 初始范围信号

- 工作流选择：`bugfix`，标记为 `workflow-selected`；这是本次自定义计划的基础范围。 [scope]
- 本次内容范围包括文档、导航链接、项目自定义规则、技能、辅助脚本，以及经证据确认不再使用的依赖或环境配置；具体删改在盘点后逐项确定。 [Q5][Q6][Q7]
- 本次保持网站和接口的现有行为，不修改 AWS 资源；所谓“重复功能”主要指学习过程中留下的过时或重复资料与配置。 [Q5][Q7]
